本项目基于 tornado，服务微信小程序「关关雎鸠」。

启动：
1. 配置 venv，执行 pip install -r requirements.txt
2. mkdir /tmp/logs/
3. 执行 sql 目录里的建表语句
4. 配置 app.conf（容器里由环境变量生成）
5. python main.py

下面是从语音录入到合适 / 不合适的产品规则。以当前代码为准。

一、语音录入

语音是见面的第一步。已经出现双心（约好见面）、半实心（只有一方合适）、实心（双方合适）时，不能再录音。单心、无心、心碎仍然可以录。

录音上限 5MB。原始语音先加密，再和提示词一起交给模型抽取。没提到的属性保持原值，不猜测。

期望性别必须和自己相反。相同则这次语音整段不写入。自己的性别还没存时，用这次话里的性别来比；这次没说期望性别时，用已经存下的期望来比。

性别、出生年份、身高、籍贯一旦有了值，以后的语音对不上就保留旧值，其它属性照常更新，并提示等待人工客服确认。体重、现居、学业、职业、收入、房产、婚姻、吸烟、饮酒、兴趣，以及全部期望，可以被新的说法覆盖。

二、资料

搜集页按固定顺序展示全部属性，没说到的一侧留空。带 * 的是见面前必须填好的个人信息：性别、出生年份、身高、体重、籍贯。这五项不齐，不能发起或加入见面。

见面详情里看对方时，只展示「ta 的信息」或「ta 的期望」至少有一边有值的属性。

顺序如下。期望没填的维度当作不限。

1. 性别 *。男 / 女。期望必须是异性，和自己相同则拒绝。
2. 出生年份 *。自己是单值，期望是闭区间。
3. 身高 *。单位厘米。自己是单值，期望是闭区间。
4. 体重 *。单位千克。自己是单值，期望是闭区间。
5. 籍贯 *。文本，两边相等才算符合；期望为空或「全部」则不限。
6. 现居。文本，规则同籍贯。
7. 职业。文本。
8. 收入。自己是月收入（元），期望是闭区间。
9. 毕业学校。文本。
10. 第一学历。高中及以下 / 专科 / 本科 / 硕士 / 博士。期望选了具体一项才要求相等。
11. 专业。文本。
12. 是否购房。未购房 / 已购房。
13. 在哪里购房。文本。
14. 婚姻。未婚 / 离异 / 丧偶。
15. 吸烟。不吸烟 / 偶尔吸烟 / 经常吸烟。
16. 饮酒。不喝酒 / 偶尔喝酒 / 经常喝酒。
17. 兴趣。文本。

加入一场已经有人的见面时，用自己的资料去对邀请人的期望。空场不比这些条件。

三、首页列表

心形从高到低：实心、半实心、心碎、双心、单心、无心。同级再按每 10 公里一档由近到远，同档按见面时间由近到远。实心最多显示一条。

双心、半实心、实心、心碎一直留在列表里。

单心和无心同时要满足：100 公里内、未来 14 天内、还没开始。另外，还没约上的场次按距离计时：10 公里以内只留 1 小时，每再远 10 公里多留 1 小时（20 公里 2 小时，以此类推）。到点仍没约上，就从列表消失。10 公里、20 公里这些整档算在这一档里。

四、约见面

一场座位只有空闲、邀请中、已约上。男写男座，女写女座。

空场可以发起，变成邀请中。邀请中、且自己的资料符合对方期望，可以加入，变成已约上。邀请中可以取消，退回空场。已约上之后，在出现「合适 / 不合适」之前也可以取消，退回邀请中，对方仍留在座位上。这一次取消记为爽约。只撤回自己发起、对方还没加入的邀请，不算爽约。

同一个人同时只能有一场「待见面」。已经双方合适之后，不能再发起、加入，也不能在别的场再选合适。半实心和心碎不占这两个名额。

发起或加入时，同一天已经坐在别的场里，也视为时间冲突。

五、见面之后

双方都约上、且都还没表态，是双心，文案「待见面」。

开始后 1 小时内仍可取消，不能选合适或不合适。满 1 小时后取消消失，出现合适、不合适。

合适、以及从不合适里恢复，只记自己。这时双方都是半实心。对方原来是不合适的，会先清成未表态。双方都选了合适，才变成实心，文案「在一起」。

不合适、以及从实心里结束关系，写成双方同一个结果，双方都是心碎。心碎盖过对方的合适。这一下会用小程序订阅推给对方。

满 7 天双方都还没表态，下一次打开首页或详情时，写成双方合适。

合适之后可以结束关系。不合适之后可以恢复关系，恢复后先回到半实心。

六、提醒和付费

所有推送都走微信小程序订阅消息。详情页点「开启见面提醒」，或发起、加入、取消之前，会向用户要一次订阅。点允许才增加一次可发送额度，openid 加密保存。额度用完需要再允许一次。

注册时用微信的手机号按钮授权。号码按敏感信息加密保存。订阅消息没有额度，或被微信拒绝时，用这个号码发短信。短信地址配在 app.conf 的 sms 段：sms_url、sms_token。请求体是 {"messages":[{"phone":"","text":""}]}，token 放在请求头 X-Sms-Token。没配 sms_url 就只记日志，短信不发出去。短信发出后，这场这次提醒不再重发。

推送内容：

1. 有人加入。推给原先坐着的人。
2. 已约上后有人取消。推给留下的人。取消的人另外收到爽约提醒，里面写明之后每次要付多少。
3. 见面开始前 1 小时。推给双方。文案让他们到店和老板说：「你好老板，我十点约了人」。十点换成这场的实际钟点，整点说「十点」，半点说「十点半」。
4. 开始满 1 小时、双方都还没选合适或不合适。推给双方，请尽快决定。未选满 7 天会视为合适。
5. 邀请中的场次离开始不到 15 分钟还没人加入。推给发起人，这场快从列表消失。
6. 一方选择不合适，或从实心里结束关系。推给对方。

没有爽约记录时，发起和加入不收费。爽约按次数累加：1 次之后每次见面 10 元，2 次之后每次 20 元，3 次 30 元，以此类推。页面上先写明次数和金额，确认后再拉起微信支付。付成之前不改座位。金额和当前次数不一致的旧支付单不用，座位没写上时退款。退款要配置商户证书，否则先记着，扫描时再试。

微信侧需要在 app.conf 的 weixin 段配置 mch_id、mch_key、pay_notify_url，退款再加 mch_cert_file、mch_key_file。订阅模板默认用小程序里那一个，字段是 thing1、time2、thing3，不对就改 subscribe_field_title、subscribe_field_time、subscribe_field_note。服务进程会自己按分钟扫描到点提醒。
